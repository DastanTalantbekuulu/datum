*   **`POST /api/v1/schemas`** — Создать новый справочник
    *   **Body:** `{ "dict_name": "currency", "definition": { ... } }`
    *   **Логика:** Валидирует структуру `definition`, проверяет, что `dict_name` уникален, и создает новый документ в коллекции `dictionaries_schema`.

*   **`GET /api/v1/schemas`** — Получить список всех справочников
    *   **Response:** `["country", "role", "currency"]`

*   **`GET /api/v1/schemas/{dictName}`** — Получить схему конкретного справочника
    *   **Response:** Возвращает JSON-документ из `dictionaries_schema` для `country`.

*   **`DELETE /api/v1/schemas/{dictName}`** — Удалить справочник
    *   **Логика:** Удаляет схему из `dictionaries_schema` и все связанные данные из `dictionaries_data` (`db.dictionaries_data.deleteMany({ dict_name: "currency" })`).

### Шаг 2: Логика `PUT /api/v1/schemas/{dictName}` (Создание новой версии)

Теперь этот эндпоинт не обновляет, а создает новую версию схемы.

**Пошаговый процесс:**

1.  **Начать транзакцию.** Это критически важно для атомарности.
2.  **Найти текущую активную версию.**
    `db.dictionaries_schema.findOne({ dict_name: "country", is_active: true })`
    Допустим, это версия 1.
3.  **Создать новую версию схемы.**
    *   Инкрементировать номер версии: `new_version = 2`.
    *   Создать новый документ схемы с `version: 2`, `is_active: true` и новой `definition`.
    *   Вставить этот документ в `dictionaries_schema`.
4.  **Деактивировать старую версию.**
    `db.dictionaries_schema.updateOne({ _id: v1_id }, { $set: { is_active: false } })`.
5.  **Важнейший момент: НЕ ТРОГАТЬ ДАННЫЕ!** Мы оставляем все старые записи с `schema_version: 1` как есть.
6.  **Закоммитить транзакцию.**


2.  **Клиент генерирует код на этапе сборки:**
    *   В `pom.xml` клиента (`Person Service`) добавляется плагин (например, `jsonschema-generator-maven-plugin` или кастомный скрипт).
    *   Этот плагин на фазе `generate-sources` делает следующее:
        a. Вызывает `GET /api/v1/schemas/country/json-schema`.
        b. Использует библиотеку (например, **JavaPoet**) для генерации Java-файла `Country.java`.
        c. Кладет этот файл в папку `target/generated-sources/`.
```xml
<build>
    <plugins>
        <!-- ... другие плагины -->

        <!-- Плагин для выполнения нашего Java-кода генератора -->
        <plugin>
            <groupId>org.codehaus.mojo</groupId>
            <artifactId>exec-maven-plugin</artifactId>
            <version>3.1.0</version>
            <executions>
                <execution>
                    <!-- Фаза, на которой выполняется плагин. generate-sources - идеальна. -->
                    <phase>generate-sources</phase>
                    <goals>
                        <goal>java</goal>
                    </goals>
                </execution>
            </executions>
            <configuration>
                <!-- Главный класс, который будет выполнять всю работу -->
                <mainClass>com.yourcompany.person.codegen.SchemaGenerator</mainClass>
            </configuration>
        </plugin>
    </plugins>
</build>
```
